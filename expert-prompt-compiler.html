驱动专家对话

平台的价值在于编译。把面向人类审核的决策卡片，自动转换成 LLM 能稳定执行的指令集。卡片是死的规则，LLM 是概率模型；编译的意义在于用结构化约束消除概率漂移。
Three-Layer System

三层提示词体系

Layer 1 · 常驻

常驻层

始终加载，定义「这个专家是谁」和「绝对不能做什么」

  • 专家人设 — 身份、语气、风格
  • 全局安全规则 — 红线、转介、免责
  • 能力边界声明 — 擅长什么、不做什么
Layer 2 · 动态

动态层

按能力模块组织，根据用户意图实时加载对应模块的决策树指令

  • 完整决策树 → 分步指令
  • 判断规则 + 追问路径
  • 转向条件 + 示例 case
Layer 3 · 检索

检索层

全量卡片做 embedding 索引，运行时实时检索补充细节

  • 细节知识片段 — 穴位、体质、禁忌
  • 避免模块 Prompt 过长
  • 实时按需注入
常驻层管「像不像」，动态层管「怎么聊」，检索层管「聊什么细节」
Compile Strategy

编译策略

编译不是模板渲染——是把人类可读的决策规则，转换成 LLM 能稳定执行的分步指令。

增量分级

增量等级
含义
编译策略
高增量
大模型完全不会
核心指令，强制语气，配 few-shot 钉死路径
中增量
大模型会但不稳定
约束条件，提醒 + 纠偏
低增量
大模型本来就会
不放进 prompt，仅验证时校验没退步

置信与审核状态

状态
编译策略
语气示例
已确认 + 高置信
正常确定语气
「根据经验，入睡困难首先要区分三种类型」
已确认 + 中置信
加柔化表达
「通常来说……但不同情况可能有差异」
有争议 ⚠️
呈现多观点，不下定论
「关于这个问题有两种看法……」
低置信 ❓
加专业建议
「这方面建议咨询专业医师确认」
已废弃 ❌

Workflow

平台工作流

📋

导入

创建专家项目，配置身份/模块/规则/风格，导入质检通过的决策卡片

⚙️

编译

自动将卡片编译为三层提示词，按增量分级 + 置信策略差异化注入

🧪

验证

用卡片示例 case 自动批量测试，验证路由/路径/边界/跨模块跳转

🚀

发布

验证通过后三层提示词打包输出，下游对话产品直接接入
